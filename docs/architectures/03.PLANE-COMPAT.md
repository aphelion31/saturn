# 03. Plane compatibility

## Schema

`migrations/0001_schema.sql` is `pg_dump --schema-only` of a database migrated by Plane's own Django
migrations, so the tables, constraints and indexes are Plane's. `0002_defaults.sql` adds database defaults
for columns whose defaults Django keeps in Python (`id = gen_random_uuid()`, `created_at = now()`, JSON
defaults, blank strings), which lets Saturn insert rows with plain SQL. These defaults do not change how
Plane itself behaves, so the same database can be served by either.

Regenerate both from a Plane checkout when Plane changes its models:

```bash
tools/plane-schema.sh ../plane
```

On startup Saturn applies migrations it has not applied yet (table `saturn_migrations`). On an existing Plane
database it detects the `issues` table, records `0001_schema` as applied and only adds the defaults.

## Sessions and passwords

- Sessions live in Plane's `sessions` table. `session_data` uses Django's signing format
  (`signing.dumps(..., salt="django.contrib.sessions.SessionStore", compress=True)`), keyed by `SECRET_KEY`.
- The `session-id` cookie holds the 128-character session key, `admin-session-id` the god-mode session.
- Passwords are Django `pbkdf2_sha256` hashes. Saturn verifies existing hashes and writes new ones with
  Django's default 1,000,000 iterations, so users move between Plane and Saturn without a reset.

Unit tests in `src/session.rs` check signing, password hashing and the session auth hash against values
produced by Django 5.2.

## API shapes

Handlers return the JSON Plane's DRF serializers produce: field names, nested objects, UUID strings,
ISO timestamps, `201` on create and `204` on delete. Plane's TypeScript types in `web/packages/types` are the
contract the apps compile against.

## Porting status

Ported: instance info, god-mode admin sign up / sign in / session, app and space sign in / sign up /
sign out, email check, current user, profile, settings, onboarding, project states.

In progress (one module each, see `WORKERS.md`): workspaces, projects, work items, cycles, modules, views and
intake, pages, notifications and home, assets, public boards.

Not ported: magic-link and OAuth sign in, email sending, webhooks delivery, importers and exporters,
integrations (GitHub, Slack), AI features, analytics exports.
