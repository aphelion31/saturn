# 01. Overview

## What Saturn replaces

| Plane                                         | Saturn                                                         |
| --------------------------------------------- | -------------------------------------------------------------- |
| Django + DRF API (`apps/api`, gunicorn)       | Rust, axum (`src/`)                                            |
| Django ORM                                    | sqlx with hand-written SQL, same tables                        |
| Celery workers + beat, RabbitMQ               | Work done inline in the request (see limits)                   |
| Redis (cache, sessions cache, throttling)     | Nothing: Postgres answers fast enough without a cache layer    |
| Node live server (`apps/live`, Hocuspocus)    | Planned in `src/pages.rs` (collaborative page editing)         |
| Node SSR for `apps/space`, `serve` for SPAs   | Static files served by the same binary                         |
| Caddy proxy (`apps/proxy`) routing 5 services | One process, one port                                          |
| MinIO / S3 uploads                            | Disk storage under `STORAGE_DIR` (planned in `src/assets.rs`)  |

Plane self-hosted runs about nine containers (web, space, admin, live, api, worker, beat-worker, migrator,
proxy) plus Postgres, Redis, RabbitMQ and MinIO. Saturn runs one binary plus Postgres.

## Request paths

**Apps.** `GET /` serves `web/apps/web/build/client` (the main app), `/god-mode` the admin app, `/spaces` the
public boards app. Unknown paths fall back to each app's `index.html`, so client-side routing works.

**API.** The apps call `/api/...` and `/auth/...` on the same origin with the `session-id` cookie.
`CurrentUser` (in `src/common.rs`) loads the Django session row from `sessions`, verifies its signature with
`SECRET_KEY` and checks `_auth_user_hash`, so a password change signs out other sessions as in Plane.
`/api/instances/*` uses the separate `admin-session-id` cookie, as Plane does for god-mode. Public API
clients send `X-Api-Key` (rows in `api_tokens`).

**Writes.** Cookie-authenticated POST/PATCH/DELETE requests must carry an `Origin` that matches the host or
`WEB_URL` (`web::origin_check`), the same rule as Plane's `BaseSessionAuthentication.enforce_csrf`.

**Auth.** Sign in and sign up are HTML form posts answered with a 302. Errors return to the app as
`?error_code=5065&error_message=AUTHENTICATION_FAILED_SIGN_IN`, which the apps already render.

## Limits

- **No background jobs.** Email (magic codes, invites, notifications), webhooks, exports, imports and
  analytics snapshots that Celery runs are not sent. Magic-link and OAuth sign in are off; email and password
  sign in works.
- **Unported endpoints answer 501** with `{"error": "Not implemented in Saturn"}` and log `unported endpoint`,
  so gaps are visible rather than silent.
