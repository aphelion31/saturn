# 04. Deploy

## Build

```bash
cargo build --release              # target/release/saturn
scripts/build-web.sh               # web/apps/{web,admin,space}/build/client
```

Copy the binary and the three `build/client` folders (keeping the `<app>/build/client` layout) to the server.

## First run

```bash
createdb saturn
DATABASE_URL=postgres://.../saturn ./saturn migrate
```

Then either open `https://your-host/god-mode/` and create the instance admin, or seed one from the shell:

```bash
DATABASE_URL=postgres://.../saturn ./saturn seed admin@your-domain 'a-long-Passw0rd' "Your company"
```

## Run

```bash
DATABASE_URL=postgres://user:pass@host/saturn \
SECRET_KEY=$(openssl rand -hex 50) \
WEB_URL=https://plane.your-domain \
WEB_DIR=/srv/saturn/web \
STORAGE_DIR=/srv/saturn/storage \
BIND=127.0.0.1:3000 \
./saturn
```

Put a TLS reverse proxy (Caddy, Traefik, nginx) in front. When `WEB_URL` starts with `https://` the session
cookies are marked `Secure`. Keep `SECRET_KEY` stable: changing it signs everyone out.
Sign-in, sign-up and email-check are rate limited per client IP (`SATURN_RATE_LIMIT`, default 10 per minute,
`0` disables). Behind a reverse proxy set `TRUST_PROXY=1` so the first `X-Forwarded-For` hop is used; without
it the TCP peer address is used and the header is ignored (so clients cannot spoof it).
Back up the database and `STORAGE_DIR` together.

## Scheduled jobs

Saturn runs Celery beat scheduled background tasks in-process as Tokio tasks.
To prevent concurrent runs across multiple Saturn instances pointing to the same database, each job
acquires a PostgreSQL transaction-level advisory lock (`pg_try_advisory_xact_lock`) before execution.

| Job name | Schedule (UTC) | Description |
|---|---|---|
| `hard_delete` | Daily 00:00 | Hard-deletes soft-deleted records older than `HARD_DELETE_AFTER_DAYS` (default 60) |
| `archive_and_close_old_issues` | Daily 01:00 | Archives and closes old issues based on project `archive_in` and `close_in` settings |
| `delete_old_s3_link` | Daily 01:30 & 03:45 | Expires export files older than 8 days and clears exporter download URLs |
| `delete_unuploaded_file_asset` | Daily 02:00 | Deletes unuploaded assets older than `UNUPLOADED_ASSET_DELETE_DAYS` (default 7) |
| `delete_api_logs` | Daily 02:30 | Deletes API activity logs older than `API_ACTIVITY_LOG_RETENTION_DAYS` (default 14) |
| `delete_email_notification_logs` | Daily 02:45 | Deletes email notification logs older than `EMAIL_LOG_RETENTION_DAYS` (default 7) |
| `delete_page_versions` | Daily 03:00 | Prunes excess page versions, keeping the latest 20 versions per page |
| `delete_issue_description_versions` | Daily 03:15 | Prunes excess issue description versions, keeping the latest 20 per issue |
| `delete_webhook_logs` | Daily 03:30 | Deletes webhook delivery logs older than `WEBHOOK_LOG_RETENTION_DAYS` (default 14) |
| `unsnooze_expired_intake_issues` | Every 5 min | Returns snoozed intake items whose `snoozed_till` has lapsed back to pending status |

Telemetry metrics pushing (`push_instance_metrics`) is intentionally not ported.

### Environment variables

- `SATURN_JOBS=0`: disables all background scheduled jobs on the instance (useful when running dedicated job workers or in test environments). Defaults to enabled.
- `HARD_DELETE_AFTER_DAYS`: retention window for soft-deleted rows (default: 60 days).
- `UNUPLOADED_ASSET_DELETE_DAYS`: retention window for unuploaded file assets (default: 7 days).
- `API_ACTIVITY_LOG_RETENTION_DAYS`: retention window for API activity logs (default: 14 days).
- `EMAIL_LOG_RETENTION_DAYS`: retention window for email notification logs (default: 7 days).
- `WEBHOOK_LOG_RETENTION_DAYS`: retention window for webhook delivery logs (default: 14 days).

### Running jobs manually from CLI

Any job can be executed once on demand:

```bash
DATABASE_URL=postgres://.../saturn ./saturn jobs run <job_name>
```

Example:

```bash
DATABASE_URL=postgres://.../saturn ./saturn jobs run archive_and_close_old_issues
```

## Existing Plane database

Point `DATABASE_URL` at a copy of the Plane database and set `SECRET_KEY` to Plane's value. Users keep their
passwords and sessions. Stop Plane's api, worker and beat containers before pointing production at Saturn.

Saturn has no SMTP delivery. `SATURN_DEV_LOG_TOKENS=1` logs magic codes and password reset links
at info level for local development. These are bearer credentials: never enable this on a shared or
production system, and restrict access to logs and the `saturn_magic_codes` database table.
