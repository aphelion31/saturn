# 02. Branch

Saturn uses an integration branch (`develop`) and a release branch (`master`), and every work branch
carries an `STN-<number>` ticket prefix.

| Branch                          | Purpose                                                                       |
| ------------------------------- | ----------------------------------------------------------------------------- |
| `master`                        | Released code only. Moves when a release or hotfix is merged. Tagged `vX.Y.Z` |
| `develop`                       | Default and integration branch. All work branches start here and merge back   |
| `STN-NNN/<type>-<description>`  | Feature, fix, refactor, docs or chore work, cut from `develop`                |
| `release/<version>`             | Release preparation, cut from `develop`, merged into `master` and `develop`   |
| `hotfix/<version>`              | Urgent production fix, cut from `master`, merged into `master` and `develop`  |

Direct pushes to `develop` and `master` are blocked by the `pre-push` hook; work arrives by pull request.

## Work branch name

```text
STN-<number>/<type>-<description>
```

- **`STN-<number>`**: three or more digits, zero-padded: `STN-001`, `STN-042`, `STN-1205`. Use the ticket
  number if there is one, otherwise the next number after the highest `STN-*` branch on origin.
- **`<type>`**: one of `feat`, `fix`, `refactor`, `perf`, `docs`, `test`, `build`, `ci`, `chore`, `core`,
  `style`, `revert`. `core` is for changes to the foundation the rest builds on (router, auth, sessions, schema).
- **`<description>`**: free text in lowercase kebab-case.

Examples:

```text
STN-001/chore-repo-tooling
STN-014/feat-cycles-api
STN-015/fix-issue-sequence-race
STN-016/core-postgres-listen-notify
STN-017/docs-deploy-guide
```

Not allowed: `feature/cycles`, `STN-1/feat-x` (number too short), `STN-015/Feat_Cycles` (not kebab-case),
`STN-015/cycles` (no type).

## Rule: pull before you work

Every time you switch to `develop`, pull before doing anything else:

```bash
git switch develop
git pull origin develop
```

A stale `develop` produces branches based on old code and conflicts in the PR.

## Create a work branch

```bash
scripts/new-branch.sh feat-cycles-api           # picks the next STN number, cuts from origin/develop
scripts/new-branch.sh STN-020/fix-login-loop    # or give the full name
```

By hand:

```bash
git fetch --prune
git branch -r | grep -oE 'STN-[0-9]+' | sort -t- -k2 -n | tail -1   # highest number on origin
git switch -c STN-021/feat-short-description origin/develop
```

## Release and hotfix branches

These are the only branches without an `STN` prefix.

```bash
git switch -c release/0.2.0 origin/develop     # bump version, final fixes, then PR into master
git switch -c hotfix/0.2.1 origin/master       # urgent fix, PR into master, then into develop
```

After a release or hotfix merges into `master`, merge `master` back into `develop` through a PR so the two
do not drift. See [03.GIT-PR-FLOW.md](03.GIT-PR-FLOW.md).

## Enforcement

`pre-commit` and `pre-push` (`scripts/check-branch.sh`) reject any other branch name. `pre-push` also blocks
direct pushes to `develop` and `master`. The `Lint PR` workflow checks the head branch of every pull
request. Install the hooks with `git config core.hooksPath .githooks`.
